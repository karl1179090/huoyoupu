# sales-returns Specification

## Purpose

允许对原销售订单的部分商品或数量办理退货，并分别追溯销售调整、实际返库和退款，使未返库或未退款的退货仍能准确表达销售情况，防止多次回补同一来源。

## Requirements

### Requirement: 部分退货确认
系统 MUST 允许管理员按原订单明细及整数基础数量确认部分退货；数量不得超过原有效销售扣除已有退货后的可退量。确认时 MUST 调整销售额、毛利和客户往来，不等待实际返库或退款。

#### Scenario: 未付款订单退部分商品
- **WHEN** 某未付款订单确认部分退货
- **THEN** 相应应收和销售指标立即减少，实际收款、退款和库存均不自动发生

#### Scenario: 超量退货
- **WHEN** 本次加累计退货数量超过可退数量
- **THEN** 整次确认失败，不产生销售信用额或库存变化

### Requirement: 原成交金额与批次来源
系统 MUST 按原订单版本的实际成交净额及成本记录分配退货金额，使用原销售批次；默认后扣先退，允许指定原批次。累计退回金额和成本 MUST 不超过相应来源可退部分，尾差可核对。

#### Scenario: 优惠后的部分退货
- **WHEN** 原商品已分摊整单优惠，用户确认部分数量退货
- **THEN** 使用分摊后的原成交金额计算退货信用额，不按商品当前默认售价退款

#### Scenario: 新进价不同
- **WHEN** 当前商品进价已经变化，原订单发生退货
- **THEN** 仍使用原销售批次成本，不用新入库成本替换

### Requirement: 独立实际返库
系统 MUST 仅在管理员记录实际返库数量时恢复原出库仓库和原销售批次库存，支持分次返库；确认退货、登记退款或重试请求均不能重复恢复库存。

#### Scenario: 先退货后返库
- **WHEN** 已确认退货 5 瓶，今日实际仅返库 3 瓶
- **THEN** 仅恢复原批次 3 瓶，剩余 2 瓶保持未返库并可继续追踪

#### Scenario: 返库请求重试
- **WHEN** 同一实际返库请求重复提交
- **THEN** 返回原记录，库存只增加一次

### Requirement: 返库退款状态与不可售成本
系统 MUST 分别展示确认退货、实际返库和实际退款状态；未返库数量不计入可售库存，明确不返库或报损的原成本单列损失，待返库不能直接冒充已损失或已入库。

#### Scenario: 已退款仍未返库
- **WHEN** 退货已确认且现金已退，但货物尚未实际返库
- **THEN** 退款记录有效，库存不增加，并显示未返库数量及可追溯成本
