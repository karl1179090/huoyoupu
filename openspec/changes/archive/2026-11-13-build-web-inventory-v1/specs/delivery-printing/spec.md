# Spec Delta

## Purpose

为配送提供可配置、可预览并能追溯版本的客户单据，使管理员和员工能够在允许的设备上发起打印及重打，且打印行为始终独立于订单确认、库存和利润变化。

## ADDED Requirements

### Requirement: 首版模板配置范围
系统 MUST 支持管理员配置纸型、显示字段及顺序、列宽和最小行高，校验可打印宽度与合法尺寸；长内容可换行及分页，不能因固定行高裁掉商品。完整自由拖拽编辑器不属于本首版。

#### Scenario: 配置列宽
- **WHEN** 管理员保存列宽总和超出纸张可打印区域的模板
- **THEN** 系统拒绝并指出配置问题，不保存不可用模板版本

#### Scenario: 长名称与多页
- **WHEN** 单据商品名换行且明细超过一页
- **THEN** 预览和打印保留完整内容、重复必要表头并正确展示最终合计

### Requirement: 订单与模板版本关联
系统 MUST 为模板修改生成新版本，打印请求明确关联订单版本与模板版本。订单修改后 MUST 能识别旧版打印，支持新版预览和重打，原版记录仍可追溯。

#### Scenario: 打印后改单
- **WHEN** 已发起打印的订单产生新版本
- **THEN** 系统显示旧打印对应原版本，提供新版打印数据，不直接标成新版已打印

### Requirement: 打印数据与多仓明细
系统 MUST 按选定版本提供客户、配送地址、商品、数量、成交金额和配置所需字段；同单多仓明细保持独立，仓库可作为可选字段。打印字段 MUST 使用允许清单，不返回进货价、成本或毛利。

#### Scenario: 同商品拆行分仓
- **WHEN** 一张订单同商品分两仓出货
- **THEN** 配送单保留两条明细及各自数量，不擅自合并或重复计算订单合计

### Requirement: 打印无销售副作用
系统 MUST 允许管理员与员工发起浏览器人工确认打印；预览、打印、重打和取消均不能再次扣库存、确认销售或改变毛利。

#### Scenario: 多次重打
- **WHEN** 同一订单发起三次打印或重打
- **THEN** 仅增加可追溯打印记录，订单、库存、成本及客户应收不变

### Requirement: 可观测打印状态
系统 MUST 区分已请求打印、人工确认、人工取消及客户端错误；不能将浏览器返回或打印事件自动当作纸张已出。电脑和手机均提供基本预览；打印调用须在真实设备调起系统打印服务并显示实际预览，按各平台实际支持的打印入口验证，不要求电脑与手机重复完成同一系统打印调用。本轮不以物理打印机或实纸输出为验收前置；未实际出纸不得宣称物理打印成功。

#### Scenario: 关闭打印对话框
- **WHEN** 用户关闭打印预览且没有人工确认实际出纸
- **THEN** 系统不自动标记打印机已完成，最多保存已请求等可观测状态
