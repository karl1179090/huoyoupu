# Spec Delta

## Purpose

为单商家网页系统建立管理员和员工的身份与操作边界，使电脑和手机遵守同一权限，并确保订单查询、打印及错误响应不会向员工泄漏成本、毛利或管理数据。

## ADDED Requirements

### Requirement: 会话身份与账号状态
系统 MUST 验证账号凭据并建立可撤销会话；未登录、会话失效或账号停用时拒绝受保护请求。凭据和会话秘密 MUST 不出现在业务响应、审计正文或日志中。

#### Scenario: 停用账号的旧会话
- **WHEN** 管理员停用某员工后，该员工使用原会话查询订单
- **THEN** 请求被拒绝且不返回订单内容

#### Scenario: 登录失败
- **WHEN** 用户提交错误凭据
- **THEN** 系统返回统一的认证失败响应，不披露密码或账号内部状态

### Requirement: 管理员与员工的操作范围
系统 MUST 允许管理员管理业务、账号、报表与模板；员工仅能读取全部订单和允许的订单版本、获取配送单数据及登记打印行为。两种角色 MUST 在电脑和手机上遵守相同权限。

#### Scenario: 员工直接调用写订单接口
- **WHEN** 员工绕过页面直接提交订单修改、退货、入库或收款请求
- **THEN** 系统返回权限错误且不产生任何业务变化

#### Scenario: 员工查询其他管理员开的订单
- **WHEN** 员工读取任一订单
- **THEN** 系统允许读取其配送、商品、成交金额及打印所需信息，不按开单人限制为本人订单

### Requirement: 员工响应的字段权限
系统 MUST 从员工的订单列表、详情、版本、打印数据、错误详情中移除进货价、批次成本、销售成本和毛利字段；禁止通过报表、商品批次或资金管理接口绕过限制。仅在页面隐藏字段不满足本要求。

#### Scenario: 嵌套批次数据
- **WHEN** 员工读取含多批次、多仓库的订单与打印数据
- **THEN** 响应保留配送所需字段，但所有层级均不存在成本和毛利字段

#### Scenario: 员工访问统计或 AI
- **WHEN** 员工调用固定报表、AI 查询或客户往来接口
- **THEN** 系统拒绝请求，不执行统计或模型调用

### Requirement: 账号管理保持可管理性
系统 MUST 仅允许管理员建立、停用账号及更改角色，且禁止停用或降级最后一个有效管理员；角色变更后 MUST 立即按新权限处理后续请求。

#### Scenario: 降级最后管理员
- **WHEN** 唯一有效管理员请求将自己改为员工
- **THEN** 系统拒绝并说明至少需要保留一个有效管理员

### Requirement: 关键操作审计
系统 MUST 记录订单、库存、收退款、余额、模板及权限变化的操作者、时间、来源和前后版本；审计记录不可由普通业务更新覆盖，且不能把重试当成第二次业务成功。

#### Scenario: 修改后重试
- **WHEN** 一次订单修改成功后因网络重试再次提交同一幂等请求
- **THEN** 系统返回原结果，保留一次有效业务变更及可关联的重试记录

### Requirement: Cookie 会话写请求保护
系统 MUST 对浏览器会话写请求验证允许来源及 CSRF 令牌，登录与会话轮换后发放有效挑战；会话 Cookie 不能暴露给页面脚本，跨站请求不得借用用户身份改变业务。

#### Scenario: 缺少 CSRF 的写请求
- **WHEN** 已登录浏览器提交缺少有效 CSRF 令牌的修改请求
- **THEN** 系统拒绝且不修改业务数据，不把 Cookie 存在当作完整授权
