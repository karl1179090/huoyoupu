## 已确认逻辑缺口（4组，待Gemini修复）

### 1. 取消后旧的异步添加可回流至下一次会话

来源：`BatchProductPicker.tsx`的isOpen effect（约63–74行）与addProductToSession（112–148行）。添加商品先await价格请求，完成后无条件setSessionLines追加；没有会话代次或关闭后失效判断。组件在OrderCreatePage保持挂载，关闭只令isOpen=false。

可复现条件：延迟某商品价格响应→点添加→响应前取消→关闭effect已清空→旧响应返回后仍append→再次打开时旧候选行可能出现，因为isOpen=true不再次清空。普通取消尚未改父订单，但下一次统一确认可能把上次已取消的商品加入。这是源码可确认路径，未声称已在浏览器观察。

需要：为添加/响应绑定本次会话身份，关闭/确认后使旧请求失效；不能让晚到响应写入关闭中或新开的会话。

### 2. 旧价格/旧报价可覆盖较新的行配置

来源：`BatchProductPicker.tsx:164–170`换单位价格请求返回后直接updateLine，不校验当前单位、客户、手动改价或请求代次；`OrderCreatePage.tsx:59–112`只有300ms防抖与清timer，没有取消/忽略已在途的旧报价。

可复现条件A：单位甲→乙快速切换，乙价先到、甲价后到；或换单位请求期间手填价格，晚到建议价仍覆盖手填值。条件B：订单配置A、B各发报价，B先返回后A返回，旧qA无条件setQuote，页面可能在B数量旁显示A金额。

需要：把响应与当前客户/单位/行或整单配置版本关联，仅最新有效响应可更新；手动编辑不能被旧建议价覆盖。变化后应明确报价待更新/失败，不允许把旧报价当新配置有效结果。当前确认按钮只看submitting/客户/行数，未依据报价是否对应当前配置阻断，这也需在同一回归中验证。

### 3. 小数输入被parseInt静默改成另一数量

来源：`BatchProductPicker.tsx:435–437`与`OrderLineEditor`数量onChange，手动批次数量也使用相同parseInt模式。输入1.5会成为1，2.35会成为2；min/step只是控件约束，没有保留非法输入并说明正整数要求。大于安全整数或换算溢出同样未见客户端明确错误状态。

需要：小数/非法/超范围数量明确拒绝或保留输入显示错误，阻止加入/正式提交，不截断后按不同数量继续。后台校验不能恢复已经在前端截断的原始意图。

### 4. 手选不足仅显示警告，统一加入没有校验

来源：`BatchProductPicker.tsx`计算isShortage并渲染提示，但handleConfirm（193–196行）仅检查行数，底部按钮也只按sessionLines.length禁用。manual需要12瓶而已选0或2瓶时仍可调用父onConfirm。超配与超单批余量也没有handleConfirm检查；原生max不会阻止普通button回调。

需要：会话统一确认前校验每条已选行配置，手选数量必须完整覆盖所需基础数量、批次属于所选仓且不超批次余量，错误行可定位；不足时禁加而非静默自动分配。整单同仓重复商品的最终需求仍通过已有全单quote及正式确认校验，不能用每行独立库存判断冒充全单通过。

### 必须继续修的两个残留

**全单quote代次失效过晚。** OrderCreatePage在fetchQuote开始时才`++quoteSeqRef.current`；有效配置改变后只是安排300ms timer，没有立即让旧响应和已展示quote失效。可复现时间线：配置A请求在途→改为B→B的300ms防抖尚未结束→A响应返回，代次仍相等而被setQuote；已有A报价也会一直保留。确认按钮和handler只检查quote存在，不核对该quote对应当前内容，也未以loading/dirty阻断。因此新增seq虽然能挡“B请求已发出后才回来的A”，仍不能保证配置B只有B有效报价才能提交。

请在内容变化时立即使旧请求代次/有效报价失效，或按内容标识检查，仅允许匹配当前内容的成功报价进入可确认状态；待更新和失败不能沿用旧值当最新值。该修复须同时覆盖防抖窗口、已发出的倒序响应及点击确认的时机，而不只是再加一次fetch序号。

**手动批次数量仍截断。** 当前BatchProductPicker约659行、OrderLineEditor约361行依旧`Math.max(0,parseInt(value,10)||0)`；输入1.5会变成1，validateSession看不到原始非法输入。例如需求1基础单位，手动输入1.5后变1，合计恰好满足而可加入。请像销售数量一样保留原输入、明确基础数量整数错误并禁加/禁提交，不以min/step/max属性代替校验。
