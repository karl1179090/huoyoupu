## 历史 v1/v2 的实施校核记录

统一浅色紧凑业务工作台，石板灰侧栏、白色内容、细灰边框、深绿主操作。桌面侧重表格密度，手机使用可读卡片与固定关键操作；确认后由Computer Use操作Antigravity实现真实交互，Codex不编写前端。

- OpenSpec和OpenAPI是业务依据，图中装饰性内容、文案、导航不扩张首版能力。库存图与模板图导航是局部场景示意；06的出库管理/配送管理不形成独立新业务。实施时按01主导航统一为开单、订单、商品、库存、客户往来、经营统计、模板设置。
- 开单图中的`received_at / recorded_at / id`是设计校核备注。实际用户页面省去数据库字段名，只保留中文说明“按实际入库时间、登记时间排序，同时间稳定排列”。不要引入生产日期、保质期管理。
- 金额直接展示后端结果；六位显示价不得用于重算净额或成本。所有客户、商品和日期均为虚构样例。
- 已退历史和可编辑余量是两个真实数据段，不能仅画一个“已退”标签后仍允许改历史。订单商业总额、退货信用与有效净额分别表达，不能二次扣退货。
- 净往来`netBalance`欠款为正、预收/多收为负。欠款与可用余额卡片各自非负，月结公式仍用有符号净额。
- 统计表“变化”示例按下单量，净量另列；AI只能查询，不写库存或资金。05手机假样例漏了同样下降的鸿运小店，同条件应包含丰盛/鸿运两条；实际界面必须以同一`reportRunId`返回完整表格和结果数，同一结果按钮不得重新求值。
- 模板仅纸型/字段/列宽/最小行高，不提供任意脚本、表达式或新增管理模块。列宽70+20+20+12+20+24+24=190毫米，A4边距10毫米；长名换行、多页表头和合计来自真实渲染。
- 管理员页面不代表员工权限；员工只读订单和打印，成本/毛利/管理员导航不可通过前端隐藏假装授权。
- 浏览器打印调用不代表已出纸；人工确认、取消和客户端失败应依据真实API状态，订单商业版本不因打印变化。

v1开单日期列、v1订单金额、v1往来符号、v1模板合计存在已知业务错误，均已在最新图实际纠正，不作为实施依据。暂无前端实现截图、设备出纸证据或用户设计确认。
